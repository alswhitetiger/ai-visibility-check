# 제출 문구 (원티드 AI Championship 2026)

제출 폼에 그대로 붙여넣을 수 있게 정리한 문서다. 수치는 2026-09-04 실측 기준이며,
`web/public/data/stats.json` 을 갱신하면 함께 고쳐야 한다.

---

## 서비스명

**AI Visibility Check**

## 한 줄 소개

쇼핑몰 주소 하나로, **AI가 우리 브랜드를 찾을 수 있는지**와 **사람이 들어와서 살 수 있는지**를 동시에 진단합니다.

## 서비스 링크

https://alswhitetiger.github.io/ai-visibility-check/

---

## 1. 해결하려는 문제

사람들이 검색창 대신 AI에게 묻기 시작했습니다. 그런데 쇼핑몰 운영자에게는
**"AI가 우리 가게를 어떻게 말하는지" 확인할 방법이 없습니다.** 경쟁사만 추천되고
우리는 언급조차 안 되어도, 그 이유를 알 방법이 없습니다.

저는 카페24 쇼핑몰을 직접 운영합니다. 제 브랜드를 AI에게 물어보면 "모른다"고 답합니다.
검색 최적화는 도구가 많은데, **AI 답변에 등장하기 위한 점검 도구는 없었습니다.**

실제로 국내 쇼핑몰 29곳을 점검해 보니 문제가 뚜렷했습니다.

- robots.txt 를 확인할 수 있었던 **21곳 중 12곳**은 AI 답변 크롤러를 이미 열어두고 있었습니다.
  차단이 문제가 아니었습니다.
- 그런데 전체 진단이 가능했던 **10곳 전부**, 상품 구조화 데이터가 없었습니다. **통과율 0%.**
- 가격 정보를 기계가 읽을 수 있게 노출한 곳은 20%뿐이었습니다.

**문은 열어뒀는데, 안에 읽을 게 없는 상태입니다.** AI가 들어와도 무엇을 파는 가게인지,
얼마인지 알 수 없으니 추천 후보에 오르지 못합니다. 이 서비스는 그 격차를 짚어줍니다.

## 2. AI 활용 방식

규칙 기반 검사와 LLM을 **의도적으로 분리**했습니다. 아무 데나 LLM을 부르지 않았습니다.

**(1) LLM 없이 판정 — 진단의 약 70%**

"AI가 우리를 못 찾는 이유"의 대부분은 파싱만으로 답이 나옵니다. LLM을 쓰면
느려지고, 비싸지고, 무엇보다 **답이 흔들립니다.** 판정 근거가 명확해야 하는 항목은
전부 규칙으로 처리했습니다.

- robots.txt 를 그룹 단위로 파싱해, AI 크롤러 14종 각각에 어떤 규칙이 적용되는지 판정
  (정확 일치 그룹 우선, 없으면 와일드카드)
- 크롤러를 **답변용 7종 / 학습용 7종으로 분리** — 답변용만 점수에 반영합니다.
  학습 데이터 수집을 막는 것은 정당한 사업 판단이므로 감점하지 않습니다.
- llms.txt, JSON-LD 구조화 데이터, JS 렌더링 의존도, sitemap, canonical,
  가격·사업자정보 노출, 모바일 뷰포트, 이미지 대체 텍스트 등 14개 항목

**(2) LLM 사용 — 측정이 필요한 지점에만**

핵심 질문 하나에만 씁니다. **"AI에게 이 브랜드를 물으면 뭐라고 답하는가?"**
브랜드 인지 여부, 카테고리 추정, 먼저 떠올리는 경쟁사, 잘못 알고 있는 정보를
한 번의 호출로 받아 구조화된 JSON으로 돌려받습니다.

여기서는 **LLM이 도구가 아니라 측정 대상**입니다. 그래서 오픈 모델로 대체하지 않았습니다.
사람들이 실제로 쓰지 않는 모델이 "모른다"고 답해봐야 의미가 없기 때문입니다.

**(3) 서비스가 멈추지 않는 구조**

AI 호출이 실패해도 진단 결과는 그대로 나옵니다. 3단 폴백과 응답 보관소를 두었고,
전부 소진돼도 사전 계산 결과가 화면을 채웁니다. 심사 기간 내내 링크가 살아 있어야
한다는 요건을 구조로 보장했습니다.

## 3. 사용한 AI 도구

| 구분 | 도구 |
|---|---|
| 진단·측정 (런타임) | **Google Gemini API** — `gemini-3.5-flash-lite` |
| 폴백 2단 | OpenAI API (키 등록 시 자동 활성화) |
| 폴백 3단 | Anthropic Claude API (키 등록 시 자동 활성화) |
| 개발 도구 | Claude Code (설계·구현·검증), Codex |

리포트 하단에 **어떤 모델이 답했는지 항상 표기**합니다. 보관된 응답을 쓸 때는
수집 날짜를 함께 밝힙니다.

## 4. 기술 구성

```
GitHub Pages (React + Vite)      제출 링크. 화면과 사전 계산 결과. 항상 작동
        │ fetch
Cloudflare Worker + D1           수집 · AI 호출 · 캐싱 · 사용량 제한
```

API 키는 프론트에 존재하지 않으며 Worker secret 으로만 주입합니다.
전 구간 무료 한도 안에서 운영됩니다.
